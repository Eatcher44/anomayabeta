- Account deletion runs only in the delete-account server function: user id from verified JWT, idempotent steps, auth user deleted last; any new user-owned table or storage folder must be added to it. Why: Google Play compliance and no orphan data.
- New uploads pass through secure-upload with durable service-only tickets; unresolved tickets block deletion finalization without timeout-based guessing, and no SQL lock spans Storage calls. Why: a late storage commit must never follow completed account deletion.
- Photo pickers settle only on native change/cancel events, supersede prior pickers and clean listeners; creation stages a local file until explicit save with a synchronous single-flight guard and reuses an uploaded draft after record-save failure. Why: focus timing cannot prove cancellation and retries must not issue duplicate writes.
- Animal creation retries use a stable per-draft UUID and confirm ambiguous inserts by an owner-scoped read; updates require returned row confirmation. Why: network response loss must not create duplicates or falsely report an unconfirmed save.
- Upload recovery uses a one-shot write-start marker and immutable paths; only unstarted tickets or observed commits may resolve, with media marked deleting before removal. Why: missing Storage metadata or elapsed time cannot prove that a started upload will not commit later.
- Animal transfer creation and claims go through the authenticated secure-transfer function and service-only secure transfer RPCs; legacy claim_transfer_code and direct transfer-code/archive writes remain revoked. Why: server-issued metadata and hashed secrets cannot be forged by clients.
- Public privacy has no announcements or bottom navigation. Why: deletion instructions must remain accessible without login or onboarding.
- Keep client transfer claims and direct code writes disabled, and account deletion gated before mutations, until coordinated transfer/media authorization passes backend tests. Why: emergency containment must not reopen audited vulnerabilities.
- Trusted media bindings and persistent deletion state coordinate sensitive transactions under a common advisory mutex; ordinary writes fail busy rather than wait while holding entity rows. Why: storage calls cannot participate in database transactions and URL fields cannot authorize cleanup.
- Browser tests runtime-import Deno handlers and mock their HTTP boundary. Why: exercise authorization without Deno modules in browser types.
- Complex transfer relationships are blocked at issuance and ownership mutation under the common mutex; deletion preflight rejects foreign references. Why: historical records must not be silently detached or exposed to another owner.
- Refuse transfers with private medical or feeding note fields at issuance and claim, without rewriting their history. Why: keeping the dossier with its owner is safer than silently sharing or deleting confidential notes.
- Real integration tests use normal disposable signup sessions and an explicitly scoped test allowlist through supported data tools, never privileged public test endpoints or exposed admin secrets. Why: real authorization can be exercised without service-key access in the Deno runner.
- New sensitive documents use private owner-scoped storage and persisted object paths, never persisted signed URLs; cleanup includes this bucket and persistent feedback counters. Why: short-lived reads preserve privacy without breaking existing public animal images.
- Server-uploaded private-document reads use a narrow security-definer predicate matching auth.uid() to active trusted-media custody; never expose the service-only registry. Why: Storage service uploads have no client owner metadata, and inline registry queries cannot authorize clients under RLS.
- Feedback attribution comes from online-verified sessions; HTML is escaped and quotas are atomic service-only counters. Why: client fields and per-isolate memory cannot authorize identity or enforce durable limits.
- Gate the kitten departure PDF entry point, checklist criterion and generator with its dedicated feature flag; keep its source and deferred historical tests. Why: postponing this export must neither block departures nor affect independent document and media security.
- Transfer quotas are consumed by a separate committed RPC call before the unmetered service-only *_checked transfer RPC; quota errors fail closed (503). Why: a rolled-back business transaction must never refund a rejected attempt.
- Transfer codes require a server preview hash of the reviewed dossier plus a server-validated optional care name/product selection; claim re-verifies both and copies only the strict allowlist and selected items, with the full original kept in the sender's protected archive. Why: client consent flags or hidden UI fields cannot control medical disclosure.
- Private media uses trusted custody, secure-upload and revocable tokens; photo testing is independently allowlisted. Cache/render generations invalidate stale auth responses. Why: testing and account switches must not expose foreign media or unlock transfer/deletion.
